¿Tus VMs se ven?

Antes de instalar nada, probamos si Kali puede hablar con el Ubuntu. El resultado decide dónde instalas Docker.

Ubuntu

Paso 1. Saca la IP del Ubuntu

# Muestra la IP de esta máquina
hostname -I
  • Te sale algo como 172.16.7.19 172.17.0.1. La primera es la tuya.

Los comandos de esta página se actualizan con tu IP.

Ubuntu

Paso 2. Enciende un servidor de prueba

# Abre una página web sencilla en el puerto 8000
python3 -m http.server 8000
  • La terminal se queda "ocupada". Es normal: déjala así mientras haces el Paso 3.
Kali

Paso 3. Pide esa página desde Kali

# Pide la página al Ubuntu
curl http://IP_UBUNTU:8000
¿Qué viste en Kali?
Tus VMs se ven. Sigue con la Ruta A: Docker en el Ubuntu.
El servidor del Paso 2 no está corriendo. Vuelve a encenderlo y repite este paso.
Tus VMs no se ven. Sigue con la Ruta B: Docker en el Kali.
Ubuntu

Paso 4. Apaga el servidor de prueba

En la terminal ocupada, presiona Ctrl + C.

2

Instala Docker y levanta las apps

Elige tu ruta según lo que viste en el Paso 3.

Ubuntu

A1. ¿Ya está instalado?

docker --version
docker compose version
  • Si responde Docker version 27.x.x → ya lo tiene, salta a A3.
  • Si dice command not found → sigue con A2.
Ubuntu

A2. Instálalo (solo si no estaba)

# Actualiza la lista de paquetes
sudo apt update

# Instala curl por si no viene
sudo apt install -y curl

# Instala Docker con el script oficial (incluye Compose)
curl -fsSL https://get.docker.com | sudo sh

Tarda uno o dos minutos. Al terminar, confirma con docker --version.

Ubuntu

A3. Verifica que el servicio esté corriendo

sudo systemctl status docker

Busca active (running) en verde y sal con la tecla q. Si aparece detenido:

sudo systemctl enable --now docker
Ubuntu

A4. Úsalo sin sudo

# Te da permiso de usar Docker sin escribir sudo
sudo usermod -aG docker $USER

# Reinicia para que el permiso se aplique
sudo reboot

En internet verás newgrp docker en lugar de reiniciar. En algunas versiones de Ubuntu no existe; reiniciar siempre funciona.

Ubuntu

A5. Prueba de humo

docker run hello-world

Si ves "Hello from Docker!", quedó listo.

Ubuntu

A6. Levanta Juice Shop y DVWA

# Juice Shop en el puerto 3000
docker run -d -p 3000:3000 --name juice bkimminich/juice-shop

# DVWA en el puerto 80
docker run -d -p 80:80 --name dvwa vulnerables/web-dvwa

# Revisa que las dos estén corriendo (deben decir "Up")
docker ps

B6. Levanta Juice Shop y DVWA

Son exactamente los mismos comandos que en el Ubuntu:

# Juice Shop en el puerto 3000
docker run -d -p 3000:3000 --name juice bkimminich/juice-shop

# DVWA en el puerto 80
docker run -d -p 80:80 --name dvwa vulnerables/web-dvwa

Kali

B7. Ábrelas en el navegador de Kali

Las apps corren en el mismo Kali, así que las abres con localhost ("esta misma máquina").

  • Juice Shop: http://localhost:3000
  • DVWA: http://localhost → usuario admin, contraseña password → Create / Reset Database
Tu objetivo para nmap: localhost

Comprueba con nmap

Tu objetivo depende de tu ruta. Los comandos ya traen el tuyo: la IP del Ubuntu.

Kali

# Revisa los 1000 puertos más comunes
nmap IP_UBUNTU
Kali

# -sV = detecta el servicio y su versión
nmap -sV IP_UBUNTU

Ayuda rápida

Para cuando algo no sale o quieres repasar.

Comandos básicos de Docker
ComandoPara qué sirve
docker psVer los contenedores que están corriendo
docker ps -aVer todos, también los detenidos
docker stop juiceDetener un contenedor
docker start juiceVolver a arrancarlo
docker rm -f juiceBorrarlo (para empezar de cero)
docker logs juiceVer por qué falló
Reinicié mi VM y docker ps sale vacío

Los contenedores se detienen al reiniciar, pero no se borran y no hay que descargarlos otra vez.

# Vuelve a arrancar tus dos apps
docker start juice dvwa
Rompí una app

Bórrala y créala otra vez. Queda como nueva.

# Bórrala
docker rm -f dvwa

# Créala de nuevo
docker run -d -p 80:80 --name dvwa vulnerables/web-dvwa
